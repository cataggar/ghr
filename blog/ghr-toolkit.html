ghr: a toolkit for GitHub releases

Originally published on Medium.

Installing binaries from the internet can be dangerous. Piping curl straight into a shell isn't something I enjoy doing — but it's convenient, so if you trust the repo, here's one way ghr can be installed on Mac or Linux:

curl -fsSL https://raw.githubusercontent.com/cataggar/ghr/main/install.sh | sh

or on Windows:

iwr -useb https://raw.githubusercontent.com/cataggar/ghr/main/install.ps1 | iex

I trust package managers more, so if you have Homebrew installed on Mac or Linux:

brew install cataggar/ghr/ghr

or using winget on Windows:

winget install ghr

Every language ecosystem now has a way to install tools. Python tools provide a nice way to install native tools across platforms:

pipx install ghr-bin
uv tool install ghr-bin

Both pipx and uv install binaries into ~/.local/bin. ghr does the same, but the binaries come from GitHub Releases.

Installing anything from a release

Once ghr is installed, it can install self-contained executables directly from their releases:

ghr install astral-sh/uv
ghr install bytecodealliance/wasmtime
ghr install casey/just
ghr install nushell/nushell
ghr install burntsushi/ripgrep

Installing ghr with ghr

It's possible to install ghr with ghr itself — and it's the best example of what verifications are possible:

downloading ghr-0.5.2-linux-musl-arm64.tar.gz ...
downloaded 0.7 MB

verified minisign: key 9bb2e9a96876fe37 (timestamp:2026-06-11T20:45:29Z file:ghr-0.5.2-linux-musl-arm64.tar.gz commit:c58accaaa736724f0fe83023587b11aff02f7eb8 tag:v0.5.2)

https://github.com/cataggar/ghr/.github/workflows/release.yml@refs/tags/v0.5.2 issuer: https://token.actions.githubusercontent.com inclusion: tree size 1671456430 + checkpoint

GitHub's own SHA-256 is verified, the minisign signature is verified, and the sigstore bundle is verified. The minisign public key is the string that comes right after the version above — required by default whenever a release has .minisig sidecars.

Verifying the author, not just the bytes

One great thing about minisign is that it lets you verify the author. I mirror some Zig releases that I use — you can check the signature on Zig's own download page to confirm a mirrored build is genuinely theirs:

ghr install cataggar/zig@v0.16.0 RWSGOq2NVecA2UPNdBUZykf1CCb147pkmdtYxgb3Ti+JO/wCYvhbAb/U

I think forking and hosting your own releases is going to become more common for open source software in the age of AI. ghr is a tool that makes that easier — and yes, you can fork it too.
